GFM ends a table at a blank line, so a paragraph written straight under one is parsed as rows of a single cell, and the drawn table swallowed two lines of prose into its first column. The rendering now reads the end itself: a row is a line carrying a `|`, the same reading `tableAt` walks a table by, the first line without one closes the table, and the widget covers the rows alone while the walk goes on into the prose below and renders it as prose, inline code and all. The cursor test moved to that end too, so typing under a table no longer flips the table back to pipes. Beside it every line of the document gained a little padding under it, which is spacing between the lines somebody typed and costs a wrapped line nothing, CodeMirror giving each line of the document one element however many rows it draws as. A fence and a table's source are left tight, both being one surface rather than a run of lines. Pressing Enter and pressing Shift+Enter are the same key here, both writing one newline, so both get the space. [The three blocks](/explanation/live-preview.md#the-three-blocks) says where a table stops and why the parser is not asked.
* **Update**: type a `#` and the vault's tags are offered. A new `GET /api/tags` is one rg pass matching the tags themselves rather than the lines holding them, deduplicated and sorted, and the pattern is `tag.ts`'s own, so nothing is offered that the editor would not then colour as a tag: `#!/bin/sh`, `#anchor` in a URL and `note#2` are on nobody's list. The leading character in it is consumed rather than looked behind, rg's engine having no lookbehind, and cut off again on this side, which is why it is taken from the last hash and not the first. The completion joins the three `basicSetup` already mounts, on the markdown language beside the wikilink's and the todo's, and the whole vocabulary goes in every time for the reason the whole vault does behind a `[[`: CodeMirror scores the labels and keeps the best, and the labels carry their hash so `#db` is scored against `#dbt` whole. A hash at the start of a line waits for a letter, that being where a heading is opened and `#` alone saying nothing about which of the two was meant, while `#flashcards/aws` on a line of its own is the vault's own convention and is what makes refusing the line outright wrong. The archive is in the answer, alone among the scans: what is filed away is out of a search because it is not what is being looked for, and a tag is a word you are trying to spell the way you spelled it last time. The list is read again on every write rather than on a `listing`, because a tag is a word inside a note and the writes that change the vocabulary are exactly the ones the route's early return walks past. * **Update**: `<leader>gv` plays a note's video in a pane beside the note. It follows `<leader>gr` down to the reuse of the pane already open, because the two keys do the same job: put the thing the note is about next to the note about it. A pane and not an embed drawn into the text, which is the whole decision here. An embed scrolls away the moment you write three lines under it, and it takes the keyboard as soon as you click it, so the note it belongs to becomes the one place you cannot type; a pane keeps its place while the note scrolls, and every key that already moves between panes, closes one or splits one works on it with nothing added. The link is read out of the note and the first YouTube address in it wins, the pane reading its own note the way the exam pane does, so the query is the editor's own and opening the player beside a note on screen fetches nothing. The first and not the one under the cursor: a note is about one video, and reading the cursor would restart the player on every line moved. `frame-src` gained `https://www.youtube.com` beside the reader's `blob:`, one named host rather than the whole of `https:`, and `www.youtube.com` rather than the nocookie mirror, the privacy that host buys being already yours behind oauth2-proxy while the extensions worth having in a player, the blocker and the sponsor skipper, name the ordinary host first. Two things are left where they are. A click into the player is not heard, a cross-origin frame telling its parent nothing and the window-blur trick that guesses at it being more machinery than a border on the wrong pane is worth; and `?t=90` is dropped, a link to a moment opening at the start. [The video pane](/reference/editor-keys.md#the-video-pane) says what the key does and what the frame will and will not answer.
* **Update**: the pre-commit gate type-checks the frontend. `lint` already ran `ty` over the backend, so TypeScript was the one half of the repo where a type error could reach a branch and wait for CI to say so; `fe:typecheck` is now a third dependency of it. The catch it buys is the shape nothing else sees: an object built member by member against an interface, `editor.tsx` forwarding every `EditorCommands` member into the vim facet, where a missing member is a type error and nothing at runtime until the key is pressed. Biome cannot see it, being a linter rather than a type checker, and a test only sees it if somebody wrote one for that key. The gate goes from a third of a second to two, almost all of it `fe:build`, which `fe:typecheck` drags in to emit the gitignored route tree. CI lost its separate typecheck step in the same breath: `mise run lint` now fails on the same check first, so the step could never have gone red on its own. * **Update**: the player sits under the note and answers a key pressed in it. `<leader>gv` splits `col` rather than `row`, a book being a column of text that reads beside a column of notes while a player is a 16:9 box wanting the width the note wants too, so the two share the height instead. `<leader>v` then starts and stops it from wherever the cursor is, which is the rhythm the pane was built for: a sentence goes by, you stop it, you write it down, you start it again. The frame carries `enablejsapi=1` and is sent `playVideo` or `pauseVideo` across the origin, so nothing about the key moves the focus and the note never loses the cursor. Which of the two goes is read off the player rather than counted here: the pane subscribes once the frame loads and YouTube streams `playerState` back, so a video paused by a click is still known to be paused and the next press starts it instead of stopping it twice. Buffering counts as running, or a press during it would start the video again rather than stop it. The signal is a counter held by the route and handed to one pane, the pane playing for the note the press came from, the same shape `focusSignal` already had: the key is pressed in one pane and the frame is in another, and a boolean has nothing to say the second time. A press with no player open raises a number nobody is listening to, which is a key that does nothing rather than one that has to check first. [Playing it without leaving the note](/reference/editor-keys.md#playing-it-without-leaving-the-note) says what the key does and what it cannot hear.
* **Update**: a note remembers where each of its videos got to. `noteVideos` answers with every YouTube link a note carries rather than the first alone, each one once, so a note about a course holds a lecture per section and `n` and `p` step through them with the header counting `2/5`. The position lives in `watching: {iDulhoQ2pro: 77, TQQlZhbC5ps: 118}`, keyed by the video's own id: reordering the note moves nothing, and two lectures in one note cannot overwrite each other, `setWatched` reading the other entries back out and writing them again. Flow style on one line because `setField` writes a line at a time and a block mapping would be indented lines it reads as belonging to the field above; it is ordinary YAML and `frontmatter.py` reads the same mapping. The write is reported on the edge rather than on the state, a player streaming its state while it plays and a report per delivery being one that never settles, so stopping is the moment worth writing and it happens once. Which route the position takes into the note turns on the focus, and the two are complementary. The focused pane's note is one somebody may be typing in, so the position is edited into the buffer with `addToHistory` off, the autosave carrying it out and `u` never taking a bookmark back; a note anywhere else goes through the reader's own guarded write, whose whole rule is that it refuses the focused pane's note. That write gained a parameter and lost its hardcoded field: the reader passes `setField(text, "reading", cfi)` and the player passes `setWatched`, and the read stays inside the guard because everything in there is about the note not moving under the write. The pane's URL is held rather than derived, a position written back into the note being a note that changed, and a URL recomputed from it would carry a new `start=` and remount the frame mid-watch. [Where you got to](/reference/editor-keys.md#where-you-got-to) says what is stored and which route it takes.
* **Update**: a release stopped rebuilding what had not changed. `shell/` had not been touched in eleven commits across three releases and was rebuilt for every one of them, four minutes on the critical path of a five minute deploy, of which two minutes was exporting a build cache and one was reinstalling three npm agents that were already in the image. The workflow now diffs the tag against the release before it, per component and along the paths that component's Dockerfile actually copies, and where nothing has moved it copies the earlier image to this release's tag with `docker buildx imagetools create`: a manifest copy inside the registry, no pull, no build, no cache export. What that hands the deploy is the digest that was already serving under the earlier tag rather than a fresh build of the same sources, which is the stronger guarantee of the two. The backend and the frontend are rebuilt on every release by construction, the version bump landing in `pyproject.toml`, `uv.lock` and `openapi.json`, so the whole of the saving is the shell. Two guards stand in front of it: a first release has nothing to compare against and builds, and a `previous` tag with no image left in the registry builds too, because a deploy pulling a tag that was never pushed is the one failure this could otherwise cause. The checkout takes the whole history now, neither the tag list nor the range existing in a shallow clone. [Cut a release](/how-to/cut-a-release.md#3-tag-and-publish) says what is rebuilt and what is copied.
