# Save path orderings: presses on a todo row

Part of [save path orderings](/reference/save-path-orderings.md). The columns are explained in [How to read the table](/reference/save-path-orderings.md#how-to-read-the-table). Rows keep their numbers on every page, so "As 82" points to the same row wherever it sits.

## Orderings

| # | Ordering | Must hold | Loses typed text if wrong | Test |
|---|---|---|---|---|
| 124 | A card dropped on another column, or a state key, whose write the vault refuses. | The card stays where the vault has it, and the notice says `Nothing moved:` and the vault's reason. The write finds its todo by its words where a line written since shifted it, if it is a root todo and exactly one line says it, as in 122. Failing that, it takes the row's line where that line is still the same todo, with the same words and indent and the same id where both carry one, and only its state and stamps moved on: a second press before the list redraws walks the todo on. Short of both it writes nothing and the notice says `Nothing moved: that line has changed since it was listed`, so it never sets the todo that now sits at the row's line. | no | home-route-todo-pane: `#397 I3 a state write the vault refuses leaves the card and says so` (red before the fix, which said nothing); `todo-api.test.ts`: `#397 B2 a state write finds its todo by its words where a line above shifted it`, `#397 B2 a state write whose line now holds another todo writes nothing` (both red before the fix, which set the todo at the row's line), `#397 B a second state press before the redraw walks the same todo on` (red before the fix, which refused the second press) (#397) |
| 125 | `t` on a row whose line a write landing since has shifted, or turned into another todo. | The timer write finds its todo the way the state write of 124 does, through the same code: by its words where a line above shifted it, else the row's line where that line is still the same todo (a second `t` before the list redraws, whose first press stamped the id, stops the session it started). Short of both it writes nothing and the notice says `Nothing moved: that line has changed since it was listed`, so it never starts or stops a session on the todo that now sits at the row's line. Before, the write took whatever todo sat at the row's line and a refusal said nothing. | no | `todo-api.test.ts`: `#529 A1 a timer press finds its todo by its words where a line above shifted it`, `#529 A2 a timer press whose line now holds another todo writes nothing` (both red before the fix, which wrote the todo at the row's line); home-route-todo-pane: `#529 A2 a timer press that cannot find its todo says Nothing moved` (red before the fix, which said nothing) (#529) |
| 126 | A state key, a card drop or `t` on one of two or more todos of the same line in one note (twins), after a write landing since. | The listing the row came from names every twin's line. Where the note now holds as many lines of those words as the listing did, the write takes the one at the row's rank among them: the second twin listed is the second twin now, however far a line above shifted them. The row's line alone cannot say this, since after a shift it holds the other twin. Twins carrying a `🆔` carry the same one, and 127 refuses those, so the rank decides only between twins with no id. Where the count differs (a twin pressed, added or taken out since, a second press before the list redraws among them) it writes nothing and the notice says `Nothing moved: that line has changed since it was listed`. A row with no twin takes the path of 124 and 125. | no | `todo-api.test.ts`: `#530 A3 a state write on the second of two twins sets the second after a line above shifted both` (red before the fix, which set the first), `#530 A4 a state write on a twin whose twins changed in number writes nothing`, `#530 I3 a second state press on a twin before the redraw never sets the other twin`, `#529 I4 a timer press on the second of two twins starts the second after a shift` (all red before the fix, which pressed the first twin); home-route-todo-pane: `#530 A5 the pane's X on a twin sets that twin after a shift`, `#530 A5 the phone strip's done on a twin sets that twin after a shift` (both red before the fix, which set the first twin) (#530) |
| 127 | `t`, a state key, a card drop or `<leader>x` on a todo whose `🆔` stands on another todo line too, in the same note (a pasted copy) or in another. | A press finds the todo's sessions, its log line and its dependents by id, so two todos carrying one id would share them all: `t` on one would close the session started on the other and write `⏱` onto the wrong line, and setting one done would unblock what waits on either. So the press checks the id first, off the reads it already makes: `t` off its search for the id, a state key and a drop off `GET /api/todos`, the pressed note off the text it just read. Where another todo line carries the id it writes nothing, re-stamps no id, and the notice says `Nothing moved: 🆔 <id> is on another todo too: <note> line <n>`, with `, and <k> more` where there are several. Session, log and `⛔` lines name the id without carrying it and do not count. `<leader>x` cycles its own line in the buffer, which autosave writes, and its parts and a recurring copy follow it as on any press, but it moves no log line and no dependent, neither as an edit to the buffer (a todo in today's own note, where both would be) nor as a write to another note, and it says the same. The press itself asks the buffer, and the page's listing of `GET /api/todos` for the other notes, since it cannot wait on the vault; the route then asks the buffer before the press for a twin in its own note, not the disk, since autosave can be a quiet period behind, so a copy pasted a moment ago is refused and a twin just changed is not. A todo with no id asks nothing more and presses as before, twins with no id by the rank of 126. | no | `todo-api.test.ts`: `#534 A1 A5 a timer press on either of two twins carrying one 🆔 writes nothing and names the other`, `#534 A2 A5 a timer press whose 🆔 stands on a todo in another note writes nothing and names it`, `#534 A3 A5 a state press, %s, whose 🆔 stands on another todo line writes nothing` (four cases), `#534 I4 a state press whose 🆔 stands on several other lines names the first and counts the rest`, `#534 A4 a <leader>x into done whose 🆔 stands on another todo line logs nothing and unblocks nothing`, `#534 B2 a <leader>x on a copy the disk does not hold yet is refused`, `#534 B2 a <leader>x whose twin the buffer no longer holds is not refused` (green on main too, which refused nothing: it guards against refusing off a stale disk); `todo-commands.test.ts`: `#534 A4 B1 a press on a twin carrying the other's 🆔 moves its own line and no log or dependent`, `#534 A4 B3 a press whose 🆔 another note carries moves its own line and no log or dependent`; home-route-twin-ids: `#534 A4 B3 <leader>x in today's note on a todo whose 🆔 another note carries moves only its line`; home-route-twin-ids: `#534 A1 A6 the pane's t on a twin carrying the other's 🆔 writes nothing and names the other`, `#534 A3 A6 the pane's X on a twin carrying the other's 🆔 writes nothing and names the other`, `#534 A3 a card dropped on done carrying another todo's 🆔 writes nothing and names the other`, `#534 A6 the phone strip's timer on a twin carrying the other's 🆔 writes nothing and names the other`, `#534 A6 the phone strip's done on a twin carrying the other's 🆔 writes nothing and names the other`, `#534 A4 A6 <leader>x on a twin carrying the other's 🆔 logs nothing, unblocks nothing and names the other`, `#534 A4 A6 the palette's cycle with vim off on a twin carrying the other's 🆔 logs nothing and names the other` (the rest all red before the fix, which pressed the line and moved whatever named the id) (#534) |
| 128 | Two `<leader>x` (or the palette's cycle) into or out of done, on two todos of one note or on one todo twice, before the first press's log write answers. | Both presses read today's daily note before either writes, so the second's write names a base the first moved past. The log write goes through the same read, change and save that `updateNote` retries on `Changed on disk`: the second press works its `## Done` line out again on the newer text, so both lines land, a then b, and a reopen drops the line the first press wrote. A note holding a stray log line retries the same way. Where today's note did not exist at either press, the second press's create is refused and it writes into the note the first made. A reopen whose listing does not name today's note yet still reads the note the disk holds. Each press's writes beyond the buffer (the twin check, the log and the write back) wait for the press before it to settle, so the lines land a then b and a reopen sees the line it drops, whatever order the answers come in. A press that never answers holds the next back only for a bound, after which the next goes on its own. Three refusals in a row still say `Nothing moved: Changed on disk`. | no | `todo-api.test.ts`: `#538 A1 two <leader>x into done in flight on one note both log, a then b`, `#538 I1 a quick reopen after done drops the line the first press logged`, `#538 I2 a stray log line in another note is dropped on the newer text`, `#538 I3 two presses on the first log of the day both log`, `#538 A2 a log write refused three times still says why`, `#538 I1 a quick reopen whose read comes before the first save still drops the line`, `#538 A1 two presses into done land a then b when the second's reads answer first`, `#538 B1 a reopen before the listing names today's note drops its line` (all red on main), `#538 B1 a reopen with no note today writes nothing and says nothing`, `#538 B2 a press that never answers holds the next one back only so long` (red before the bound); home-route-twin-ids: `#538 A3 two quick <leader>x into done with vim on both log`, `#538 A3 two quick palette cycles into done with vim off in a narrow window both log` (#538) |
| 129 | A press that recomputes dependents (a state key, a card drop, `<leader>x`, the write back to other notes) while a `⛔` names a `🆔` that two todo lines carry; or `b` picking such a todo as the blocker. | Which twin decides cannot be told, so a dependent naming that id stays as it is, `[ ]` or `[b]`, in the buffer and in every note the write back reaches, unless another of its blockers is open, which blocks it as before. The buffer counts an id as twinned where a todo in it and a todo in another note carry it. `b` on such a blocker writes nothing, stamps no id, and the notice says `Nothing moved: 🆔 <id> is on another todo too: <note> line <n>`, the check of 127. | no | `todo-write.test.ts`: `#537 A4 blockedLines leaves a dependent on a twinned 🆔 as it is, %s` (two cases), `#537 I4 a dependent with one twinned blocker and one closed blocker stays as it is`, `#537 B1 a twinned blocker beside an open one still blocks, %s` (two cases); `todo-commands.test.ts`: `#537 A5 <leader>x on another blocker leaves a dependent on a twinned 🆔 in the buffer`, `#537 A5 <leader>x leaves a dependent whose blocker another note carries too`; `todo-api.test.ts`: `#537 A5 setting d done leaves c blocked in the issue's note`, `#537 A5 the write back leaves a dependent in another note on a twinned 🆔`, `#537 A6 blocking on a todo whose 🆔 stands on another todo writes nothing and names the other`; home-route-twin-ids: `#537 A6 the pane's b on a twinned blocker says Nothing moved`, `#537 A7 the phone menu's blocked by on a twinned blocker says Nothing moved` (#537) |
