# Save path orderings: moving a todo between notes, and the edit row

Part of [save path orderings](/reference/save-path-orderings.md). The columns are explained in [How to read the table](/reference/save-path-orderings.md#how-to-read-the-table). Rows keep their numbers on every page, so "As 82" points to the same row wherever it sits.

## Orderings

| # | Ordering | Must hold | Loses typed text if wrong | Test |
|---|---|---|---|---|
| 117 | The todo pane's `m` refiles a todo from one note into its project's `index.md`. | Two writes, each once and in its note's write queue, each naming the text it read as its base: the project's note first, the note the todo left only once that has landed. The vault's answers go in the cache. | no | home-route-refile: `#396 A1 I1 I2 I8 writes the project's note first, then the daily note, once each` (#396) |
| 118 | As 117, but the project's note is not written: it fails, or is refused over its base three times. | The note the todo left is not written, so nothing moves. The notice says so. | no | home-route-refile: `#396 I1 a project's note that is not written moves nothing, and says so` (#396) |
| 119 | As 117, but the second write fails, or the todo or a line under it changed between the read and that write. | The todo stays in both notes, never in none, and the notice says so. A second `m` writes only the note the todo left when the todo carries a `🆔` and the project's note holds its whole block, every line as it stands, in a row. Short of that, a todo of the same words or a block changed since the first press, it copies the block again: a duplicate, never a loss. | yes | home-route-refile: `#396 I1 a daily note whose write fails keeps the todo in both, and says so`, `#396 I3 a part changed under the move keeps the todo in both, and says so`, `#396 I3 a second m after a half move takes the todo out without a second copy`, `#396 B1 another todo of the same words in the project's note does not stand for this one`; `todo-refile.test.ts`: `#396 B1 another todo of the same words is not the todo, so the block lands`, `#396 B2 a copy whose parts were changed since takes the block again` (both red before the fix, which took the source out over a copy of another todo) (#396) |
| 120 | `m` while either note holds text a failed save left, or while a write of either is in the air. | Nothing is read or written; the notice names the note and says why. The guards are asked again inside each write. | yes | home-route-refile: `#396 I4 writes nothing while the project's note holds text not yet saved`, `#396 I4 writes nothing while the daily note holds text not yet saved`, `#396 I4 writes nothing while a write of the daily note is still out` (#396) |
| 121 | `m` on a project with no `index.md`. | The note is made holding `## TODOs` and the todo, then the note the todo left is written. The new path goes into the listing at once, so a second press queued behind it writes into the note rather than making it again. | no | home-route-refile: `#396 I6 a project folder with no index.md gets one holding the todo`, `#396 B4 two presses back to back on a project with no index.md make it once` (red before the fix, which made it twice) (#396) |
| 122 | Two `m` presses back to back on two todos of one note, before the list redraws. | The second press finds its todo by its text where the first's write shifted it, if it is a root todo and exactly one line says it, so both move. No line, several, or a part (whose project hangs on its parent, so the same words elsewhere can be another project's todo) reads as changed, as in 119. | no | home-route-refile: `#396 B3 two presses back to back on todos of one note move both` (red before the fix, which left the second in both notes); `todo-refile.test.ts`: `#396 B3 a root todo a write has shifted is found by its words`, `#396 B a nested row whose line moved is not looked for, since its project hangs on its parent` (red before the fix, which found another parent's part) (#396) |
| 123 | A card dropped on another lane of the board, with lanes by project, including a card from "No project". | The same path as `m`, with the lane's project in place of the todo's: the orders of 117 to 122 hold as they stand, the todo's parts moving with it. There is no second move. | no | home-route-refile: `#397 A2 a card dropped on another project lane moves into that project's note, project's note first`, `#397 A2 a card with no project dropped on a project lane moves into that project's note`, `#397 I4 a dropped card's parts move with it` (all three red before the fix, which filed the todo under its own project or refused it) (#397) |

## The edit row

The rows below are the todo pane's `i`, whose line stays open across redraws (#2087).

| # | Ordering | Must hold | Loses typed text if wrong | Test |
|---|---|---|---|---|
| 149 | `i` straight after an `x`, typed into past the redraw in which the `x`'s first save of a note with no frontmatter moved the row three lines down. | The line stays open on the todo, found by the words it was typed over or where the `x` left it, with its caret and every key; Enter writes onto the line the `x` wrote. | yes | board.spec.ts: `x then i keeps the row and every typed key through the redraw, and Enter writes them`, `with vim off, x then i keeps the row through the redraw, and Enter writes it`; todo-pane.spec.ts (phone): `edit tapped after a state press keeps the row and every typed key through the redraw that moves it (#2087)` (all red on main) |
| 150 | Lines land above an open edit row, by any write. | As 149, by its words; of twins, the same one by their order while their count holds. | yes | board.spec.ts: `an edit row follows its todo when lines land above it, and Enter writes there`; `todo-api-edits.test.ts`: `#2087 an edit row through a redraw` (red on main) |
| 151 | A redraw leaves an open edit row no line to follow: its twins' count changed, or no row is left at its line. | Nothing is written; the line closes, the notice holds the whole typed text, and the pane's keys work again. | yes | board.spec.ts: `of two twins, an edit row whose twin left closes, keeping its text in the notice, and the keys work again` (red on main) |
| 152 | Enter on an edit whose line no longer holds the words it was typed over. | Nothing is written over the newer line. The notice says so and the line opens again on the typed text; a second Enter goes through the same check and lands only once the line reads as before. | yes | board.spec.ts: `an edit whose line changed writes nothing, says so, keeps the text, and goes once the line reads as before` (red on main) |
| 153 | Enter on an edit whose write fails: a `500`, the network, or refused over its base three times. | As 152: the notice, the line open again on the typed text, and Enter sends it again. | yes | board.spec.ts: `an edit that fails with a 500 says so and keeps the text for another Enter` (red on main) |
| 154 | `i`, `b` or `s` on another row of a note straight after an `x` or an edit there, whose save stamps a frontmatter block on top of a note that had none, before the list redraws. | The stamp moves every row of the note down, so the key's row, listed before it, names a line that no longer says its words. A press's save keeps how many lines it gained on top and when (`pressWrote`), and `landedRow` reads a row whose own line no longer says its words that many lines down, where they are, for one turn's wait (10 s). A row listed after the stamp reads its own line. `s` waits its turn behind the `x` like the other keys. Before, the edit was refused and stayed open, and `b` and `s` wrote nothing and said nothing (#2210). | yes | order.spec.ts: `#2210 an edit by i on another row before the x's write lands still lands, vim on` and `vim off`, `#2210 a blocker by b …`, `#2210 a part by s …` (both vims), `#2210 an edit on another row before an edit's write lands still lands`, `on a phone, before the write lands › #2210 an edit tapped on another row after a state tap still lands` (all red on main); todo-api-edits: `#2210 a row listed before a press stamped its note` |
| 155 | Enter on the prompt of `s` (a part) or `a` (a todo) whose store write is refused: a `500`, the network, or a parent deleted since it was listed (`422`). | Nothing lands. The notice says `Nothing moved:` and the store's reason, and the prompt opens again on the typed text, so Enter sends it again; a send that lands clears the notice. Escape closes it and the text is gone. `s` under a parent whose words changed since it was listed lands under it. Before, the typed text was dropped with no notice (#2212). | yes | keys.spec.ts: `#2212 an s the store refuses says why and keeps the part for Enter to send again` (both vims), `#2212 an s under a todo deleted since it was listed …`, `#2212 an a the store refuses …`; strip.spec.ts: `#2212 a part the store refuses … by tap` (all red on main) |
| 156 | `b` whose row changed or was deleted in the store since it was listed, whose picked blocker was deleted, or whose write fails. | Nothing is written and the notice says why: a stale version answers `409`, a deleted row `404`, a blocker that names no todo `422`. The picker does not open again. Before, a deleted blocker was written as an id that names no todo, holding the row blocked for good, with no notice (#2212). | yes | keys.spec.ts: `#2212 a b on a todo changed since it was listed …` (both vims), `#2212 a b whose row was deleted …`, `#2212 a b whose blocker was deleted …` (red on main), `#2212 a b the store refuses says why`; strip.spec.ts: `#2212 a blocked by on a todo changed … by tap` |
