# 2026-10-15

* **Correction**: [Saving](/reference/editor-keys.md#saving) no longer writes one note's text into another when the vault reports a write while you switch notes (#272). A write still on its way as you move a note now keeps its text under the new path if it fails; a delete, or a move made outside kasten, keeps it listed and offers it when the note is back at its path (#271).
* **Correction**: [HTTP API](/reference/http-api.md#put-apifilespath) `PUT /api/files/{path}` takes an optional `base` and refuses a write whose base the vault has moved past with `409`. The autosave sends one, so its write in the air when another writer wrote the note no longer lands over their text; the note reads `Changed on disk` instead, as [Saving](/reference/editor-keys.md#saving) says (#273).
* **Update**: The `409` of a stale `base` is now the only conflict check (#284). [Saving](/reference/editor-keys.md#saving) shows `Changed on disk` when a save is refused, not when the vault reports another writer's write. The write on page hide names a base too (#279), and every writer of a whole note (todos, highlights, bookmarks, review) names one and reads the note again on a refusal (#281). [HTTP API](/reference/http-api.md#put-apifilespath) answers a stale base with `200` and the note as it stands when the vault already holds the text sent, and writes nothing (#277).
* **Correction**: [Saving](/reference/editor-keys.md#saving) keeps every text a failed save leaves for a note, where before a second failure replaced the first, even text the buffer never showed (#280). A move onto a path that holds kept text keeps both (#282). Opening the note offers the oldest, the bar lists the rest, and `:e!` drops only the text in the buffer. A save that waited behind another and failed now reopens as `Could not save`, not `Changed on disk` (#286).
* **Correction**: [HTTP API](/reference/http-api.md#put-apifilespath) `PUT /api/files/{path}` takes a base that names the text before the server stamped it, so a page-hide keepalive typed behind a quiet write to a note without a block is no longer a false `409` (#277).
* **Correction**: [Saving](/reference/editor-keys.md#saving) no longer writes older text over newer after a failed save: a save that fails with newer text already on its way is dropped, and one that fails after the note took another writer's text is kept and listed, not put back under your cursor (#290). Moving the focus to a second pane on the same note writes the first pane's text, as leaving the note does, so typing in the second pane never drops it (#289). `:e` without the bang declines while a save is on its way (#291). Kept text of a deleted note is no longer offered to a note moved onto its path (#292).
* **Correction**: [Saving](/reference/editor-keys.md#saving) no longer puts an older save's text on screen while a newer save is on its way, from its answer or from the vault's report of it, so keys typed then are not lost (#296). Another writer's text reaches a clean screen once your last save has answered. A save that fails after the note took another writer's text is kept even when the page was hidden since (#297), and a save typed on that text names it, so it is no longer a false `Changed on disk` (#298).
* **Correction**: [Saving](/reference/editor-keys.md#saving) sends every save of a note through one queue. A save still waiting at `:e!` is never sent (#301). Hiding the page holds and resends the save to a note just left, not only the open note's (#302). Reopening a note, or focusing a second pane on it, while its save is on its way shows that text and is no longer a false `Changed on disk` (#303). A read of the text a save was typed on no longer replaces newer text on screen (#304). A save after a page-hide keepalive names the keepalive's answer, and a keepalive behind a failed save goes again (#305). A rename or a delete waits for every save on its way and refuses when one failed; hiding after a reload no longer sends the older text over it (#306). A save that fails with no answer reads the note again before the next save names a base (#307).
* **Correction**: [Saving](/reference/editor-keys.md#saving): hiding the page behind a save still waiting its turn names the last save sent, and a page-hide save that reached the vault before the save ahead of it goes again once that one lands, so neither reads as a false `Changed on disk` (#310). `:e!` while a save is on its way writes the vault's text back behind it, so the thrown-away text does not return (#311). A page-hide save from a note reopened on the text under a save still on its way names that text, so it no longer lands over the save ahead of it unasked.
