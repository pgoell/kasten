# 2026-10-19: review, todos and tags

* **Update**: [Flashcard format](/reference/flashcard-format.md#a-deck-inside-a-deck) and [Editor keys](/reference/editor-keys.md#the-review-pane) say the deck list folds the decks under a deck behind an arrow, by tap or `za`, folded at first below the top level, and [Import an Anki deck](/how-to/import-an-anki-deck.md#import-it) says the import now sits behind one **Import** entry above the decks (#517).
* **Update**: [Flashcard format](/reference/flashcard-format.md#daily-limits) gained Daily limits: `decks.md` in the config folder, how a subdeck inherits a limit, the parent rule, and how today's answers are read off the schedule. [Configuration](/reference/configuration.md) gained `KASTEN_REVIEW_NEW_PER_DAY` and `KASTEN_REVIEW_REVIEWS_PER_DAY`, and [the HTTP API](/reference/http-api.md) `GET /api/review/limits`. [Spaced repetition](/explanation/spaced-repetition.md) says why the count reads off the schedule; both "not here" lines on daily limits are gone (#519).
* **Update**: [HTTP API](/reference/http-api.md) counts forty-two `/api/` endpoints, twenty-seven reading, fourteen writing and one streaming, where it said thirty-seven; a backend test now checks the count and the sections against the app's routes (#608).
* **Update**: [Flashcard format](/reference/flashcard-format.md#sitting-one) and [Editor keys](/reference/editor-keys.md#the-review-pane) gained the sitting's Undo, `u` in the pane, which takes back the last rating or suspend, and the Center toggle, which puts the card in the middle of the pane. [Save path orderings](/reference/save-path-orderings.md#the-review-sittings-undo) gained the orders an undo can meet the sitting's write queue in (#600).
* **Update**: [Editor keys](/reference/editor-keys.md#the-review-pane) and [Save path orderings](/reference/save-path-orderings.md#the-review-sittings-undo) say a rating, suspend, reveal or jot waits while an undo is out (#600).
* **Update**: [Save path orderings](/reference/save-path-orderings.md#the-review-sittings-undo) says a jot held through an undo goes on the next submit, into the note it was opened on (#600).
* **Update**: [Flashcard format](/reference/flashcard-format.md#daily-limits) says a sitting keeps the limits it started with, and a change to `decks.md` applies from the next sitting (#612).
* **Update**: [Editor keys](/reference/editor-keys.md#todos) gained `<leader>@` and [the todo pane](/reference/editor-keys.md#the-todo-pane) `@`, which write `#agent` on a todo, take it back off an open one and refuse client work. [Todo format](/reference/todo-format.md#agent-work) gained Agent work, and [Save path orderings](/reference/save-path-orderings.md#orderings) the orders the pane's `@` can meet a note's write queue in (#523).
* **Update**: [Todo format](/reference/todo-format.md#the-fields) says what is no tag: a hash in a code span, a markdown link or a wikilink, or one straight after a letter, digit, `_` or `/`, as in a web address. [Agent work](/reference/todo-format.md#agent-work) says `@` reads `#agent` by the same rule, a field's value not counting as words, and leaves the tag in where taking it out would make a tag of what follows (#617).
* **Update**: [HTTP API](/reference/http-api.md#get-apitags) says `GET /api/tags` reads each tag off its line as the todo board does, so a hash inside a code span, a wikilink or a markdown link is no tag there either (#629).
* **Update**: [Todo format](/reference/todo-format.md#the-fields) says a todo tag has the editor's shape, a letter or `_` after the hash, then letters, digits, `_`, `/` or `-`, so `(#next)` carries `#next` and `#123` is no tag. [Agent work](/reference/todo-format.md#agent-work) says `@` reads `(#agent)` and `#agent.` as the tag and takes it off (#627).
* **Creation**: Added [Tag format](/reference/tag-format.md), the one rule every tag reader follows: a run of letters, numbers, `_`, `-` and `/` holding at least one that is no number, so `#1on1` is a tag and `#1984` and `#Ⅳ` are not, ended by any other character, and no tag in a code span, a fence or a link. Its table of cases is what each reader is tested against (#640, #636, #632, #635, #633).
* **Update**: [Todo format](/reference/todo-format.md#the-fields) reads a todo tag by that rule, so `#1on1` is a tag again. [Flashcard format](/reference/flashcard-format.md) says a deck tag ends where a tag ends, so `(#flashcards/es)` names `es` and `#flashcardsx` names none. [HTTP API](/reference/http-api.md#get-apitags) and [Graph query](/reference/graph-query.md) say `/api/tags` and a node's tags skip a hash in a fence, a code span or a link (#640, #632, #635, #633).
* **Update**: [Tag format](/reference/tag-format.md#the-rule) says a hash in an indented code block, an HTML comment or the frontmatter is no tag, and that the frontmatter's `tags` field names tags as in Obsidian. [HTTP API](/reference/http-api.md#get-apitags) says what the second `rg` pass now looks for, and [Graph query](/reference/graph-query.md) and [Todo format](/reference/todo-format.md#the-fields) name the new places (#642, #643).
* **Update**: [Tag format](/reference/tag-format.md#the-rule) says a line that opens with `<!--` starts a comment block that ends with the line holding `-->`, or with the note, and that only a `---` at the start of line 1 opens a frontmatter, which the editor now reads too: one that never closes is none (#648, #650, #651, #649). [Math and diagrams](/reference/math-and-diagrams.md#loading) says a failed diagram load retries, as KaTeX's does (#647).
