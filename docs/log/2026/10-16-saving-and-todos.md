# 2026-10-16: saving, the phone, the board and todos

* **Correction**: The hosted dev frontend installs again whenever `bun.lock` changes and then restarts vite, so a package added while it runs no longer fails to resolve (#328). A failed install serves no page, and the logs repeat bun's error. [Two environments](/explanation/environments.md), [Run the checks](/how-to/run-the-checks.md), [Deploy to the VPS](/how-to/deploy-to-the-vps.md) and [mise tasks](/reference/mise-tasks.md) say `dev:restart` is still needed after a change to `uv.lock`, but not after one to `bun.lock`.
* **Correction**: On Android the viewport meta loses `viewport-fit=cover` before the first layout, so the page lays out there as it did in 0.49.3 (#364). With cover, Chrome on Android drew the page under the system bars: on a Galaxy S22 Ultra with three-button navigation the installed app scrolled and the bottom bar sat under the buttons. A classic script in `public/` strips it, since the policy allows no inline script; Safari keeps cover and its safe-area padding (#355).
* **Correction**: The live preview tests wait for the markdown parse to finish before they look at what it drew, so a slow parse on a loaded machine no longer fails them (#365).
* **Correction**: nginx sends `Cache-Control: no-cache` with `index.html` on every route and with the files from `public/` that keep their names across releases, such as `viewport-fit.js`, the manifest, the icons and pdf.js, so an installed app checks for a new shell at each load where before it could keep the old one for days (#368). The hashed files under `/assets/` are still cached for a year.
* **Update**: Capture works with no signal (#376). A service worker, `/sw.js`, opens the installed app offline: it fetches the shell from the network first and falls back to its copy, and serves hashed assets from its cache first. nginx answers a missing `sw.js` with `404`, never the app's page. [Capture from your phone](/how-to/capture-from-your-phone.md) says a dump sent with no signal waits on the phone in IndexedDB, listed as waiting, and goes in the order it was typed once the signal returns, into the day it was typed on; and that **Waiting: sign in again** means the login ran out, since a 302 or 401 from oauth2-proxy never drops a dump. [Editor keys](/reference/editor-keys.md#capturing-into-todays-dump) says `<leader>cd` keeps the thought the same way and says when it waits. [HTTP API](/reference/http-api.md#post-apidump) says `POST /api/dump` takes an optional client `id` and writes a second POST with the same id as a no-op, keeping the ids it has seen in `dump-receipts.json`, so a send whose answer was lost never writes the thought twice. [Deploy to the VPS](/how-to/deploy-to-the-vps.md) and [kasten on a phone](/explanation/kasten-on-a-phone.md) cover the worker.
* **Correction**: A tab open across a release reaches a route it had not opened yet on the new release, where a route whose chunk preloads a stylesheet showed "Something went wrong!" (#379). The router reloads once for a missing script, and kasten's error screen now reloads once for Vite's `Unable to preload CSS` too. [kasten on a phone](/explanation/kasten-on-a-phone.md#the-app-opens-with-no-signal) says what an open tab does across a release, [Save path orderings](/reference/save-path-orderings.md) gains row 96 for the text typed before that reload, and [mise tasks](/reference/mise-tasks.md) gains `fe:e2e:release`, which proves it in Chromium against two builds.
* **Correction**: Leaving the editor route holds the text of the note's writes still in the air before the flush goes out, so a tab closed, reloaded or sent to the background before that write answers no longer loses the last typed line (#382). The route's `pagehide` listener goes with it, and the page cancelled the flush unheard. Each write landing drops its held copy. [Save path orderings](/reference/save-path-orderings.md) gains rows 97 to 101. Coming back to the note before the flush answers keeps the copy held, where the cache the leave filled read as the vault's text and dropped it. The reload after a gone route chunk now counts once per release and not once per tab session, so a tab left open across two releases reloads at each (#383).
* **Correction**: A note's write queue now lives as long as the page, not as long as one editor, so coming back to the note before the flush on leaving the route answers joins that flush's queue (#386, #387). Its failure reaches the buffer that came back, `:e!` writes behind it, and text typed after coming back goes out behind it or, if the page dies, reopens as an error, not a conflict. [Save path orderings](/reference/save-path-orderings.md) corrects row 101 and gains rows 102 to 105.
