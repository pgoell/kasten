# 2026-10-30

* **CI**: branch protection drops `require_last_push_approval`. Since the issue loop pushes as its bot account, the setting held every bot pull request for pgoell's approval, whatever paths it touched (#1339). Now only a pull request on a path in `.github/CODEOWNERS` waits, as [Approve a held pull request](/how-to/run-the-checks.md#approve-a-held-pull-request) says. `dismiss_stale_reviews` stays, so a push after an approval on such a path still needs a new one.
* **Search**: the margin's local graph gets a fourth list, Notes like this one: up to ten notes nearest the open note by the bge-m3 vectors of its pieces, each with the heading of its nearest piece, from the new [`GET /api/similar`](/reference/http-api/finding.md#get-apisimilar). Vectors only, as [Semantic search models](/explanation/models-on-the-vps/semantic-search-models.md#what-kasten-would-need) planned; part 3 of #954.
* **Agents**: search by meaning for agents, part of #954. The MCP tool `search_meaning` and `GET /agent/search/meaning` answer the finder's ranked search, at most twenty notes, or with `like` the notes like one note, at most ten, by the stored vectors. The folder named by `KASTEN_PIECES_SKIP` never shows. `search_notes` is unchanged. The vault now has eleven capabilities, as [The agent boundary](/explanation/the-agent-boundary.md) says; the route is in [Search by meaning for agents](/reference/agent-api/search-by-meaning.md).
* **Review**: a deck's open parses its cards in a worker, so a 1 MB deck no longer holds the main thread (141 ms at a 4x CPU slowdown before). A worker that cannot start or fails leaves the parse to the main thread as before. Vite builds workers as ES modules now, since the default bundle touched `document` at load (#1359)
* **Review**: a grade no longer parses the deck note again on the main thread. It shifts the cards the sitting holds, and the write's landing keeps them where the vault's answer differs only in its `modified` stamp; at a 4x CPU slowdown on the 1 MB deck a grade went from two long tasks of about 145 and 78 ms to one of about 85 ms, the write's hash (#1384). The 20-step timing test now counts each grade until its write lands, so it sees that work (#1379, #1380). New orderings G1 to G6 in [the review sitting's writes](/reference/save-path-orderings/review-sitting-undo.md#which-line-a-grade-writes-to).
* **Fix**: the pieces index waits for a lost database connection and resumes, instead of stopping until the next start. It retries after 1 second, doubling to 60, then sweeps, so saves made in the outage reach the index (#1328). See [The pieces index](/explanation/models-on-the-vps/the-pieces-index.md#when-it-stops).
* **Review**: a grade's write hashes its base in a worker, so on the 1 MB deck at a 4x CPU slowdown 20 grades make one long task of 57 ms, the worker's start, instead of one of 65 to 107 ms each. Where no worker can start, or it fails, the hash runs on the main thread as before (#1384). New orderings H1 to H6 in [the review sitting's writes](/reference/save-path-orderings/review-sitting-undo.md#the-base-a-write-names).
* **Fix**: the pieces index also waits out a full connection pool and too many connections, and no other database error ends it without a log line (#1387). See [The pieces index](/explanation/models-on-the-vps/the-pieces-index.md#when-it-stops).
* **Fix**: the pieces index starts its vault watcher again when it fails, at an inotify limit or with the vault folder gone, with the database's 1 to 60 second backoff and one log line, and sweeps after each start so no save is missed; before, the watcher ended unseen and no save reached the index until the next start (#1390). A sweep with no vault folder drops nothing. A skipped note's log line keeps only the driver's first line, without the statement, its values or the failing row (#1388). See [The pieces index](/explanation/models-on-the-vps/the-pieces-index.md#when-it-stops).
