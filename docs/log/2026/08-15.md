* **Update**: a sitting can be timed. `t` in the exam pane starts a two hour countdown, the limit all four Claude exams run to, and a count typed in front of it sets another length the way vim counts a motion, `45t`. Digits were free to take: a question is answered with the letters `A` to `J`, so nothing was listening for a number, and any other key ends a count so a length typed and abandoned cannot start a timer ten questions later. The countdown is read off an absolute deadline rather than counted down a second per tick, which is what makes a tab the browser throttled in the background come back with the right time left rather than with the seconds it was denied. Running out grades the sitting where it stands, unreached questions included, which is what the real exam does with them and is the only reason to time a practice one at all; `t` again takes the timer away, and the clock stops rather than disappearing when the sitting ends, so finishing early shows what was left. It stays in React state with the answers, so a reload still loses a sitting in progress. [Time the sitting](/how-to/write-a-practice-exam.md#time-the-sitting) says what the key does.

The default is the honest answer rather than a guess from the path, and the drift it leaves is real and accepted: a writer that knows what it makes says so in the text it hands over, so the type a note ends up with is decided by the door it came in by. Two filenames stop being stamped at all, `index.md` and `log.md` at every level of the vault, because one is a listing of the bundle and the other its history and neither is a concept document; text written to one comes back byte for byte, `okf_version` and all, and a file named that way never gets an `id`. The guard reads the canonical relative path rather than the URL's, so `ideas/./index.md` is caught, and it sits on all three writers rather than the two the rule obviously names: an Anki deck called `index` would otherwise have imported a full block. Crossing that boundary is handled in one direction only. A note renamed off a reserved name is stamped where it lands, inside the same jj bracket as the move, which covers a file with no block, one carrying `okf_version` alone and one left over from an earlier rename; a note renamed onto one keeps the block it had and the bundle stops conforming until somebody converts it, because deleting the block would delete an id and a creation date the note owns and would not be enough anyway, the body having to become a listing or a log.
