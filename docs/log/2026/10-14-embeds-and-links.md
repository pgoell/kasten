# 2026-10-14: embeds and links

* **Update**: [Editor keys](/reference/editor-keys.md) says Ctrl+click or a tap on a markdown link with a scheme, such as `[mail](https://...)`, opens the address in a new tab.
* **Creation**: Added [Embed format](/reference/embed-format.md). `![[note]]` draws the note's body in a box in place of the line, without its frontmatter, and `![[note#heading]]` draws one section, the heading through to the next heading of the same or a higher level. The target resolves as a wikilink does, an alias is ignored, `![[image.png]]` draws the picture, a missing note or heading draws `Not found`, and embeds stop three deep with a stub. The page says what is out of scope: block references, editing in place, PDF and other file embeds, and plain links with a heading or alias, which issue #206 tracks.
* **Update**: [Live preview and the vim mode](/explanation/live-preview.md) gained a section on embeds: why the box is the same rendering nested and read only, why it hides its source as a picture does, why a depth cap rather than a cycle check, why opening one needs Ctrl or a tap, and why it listens to its note rather than being rebuilt with the document. [Editor keys](/reference/editor-keys.md#wikilinks) says Ctrl+click or a tap on an embed opens its note. [Highlight format](/reference/highlight-format.md#the-figure) no longer says the editor does not draw an embed.
* **Update**: [Editor keys](/reference/editor-keys.md#wikilinks) gained a table of the forms a wikilink is written in: `[[note|alias]]` shows the alias and opens `note`, `[[note#Heading]]` opens `note` at the heading, `[[#Heading]]` jumps in the note itself, and a table writes the bar `\|`. [Embed format](/reference/embed-format.md) lost the out-of-scope line on plain links with a heading or an alias, which now resolve (#206). [Relation format](/reference/relation-format.md#how-the-graph-reads-it) no longer says the editor ignores an alias the graph cuts off.
* **Update**: [HTTP API](/reference/http-api.md#get-apivault-assets) gained `GET /api/vault-assets`, which lists every image and book in the vault so the editor can draw `[[plan.pdf]]` as live (#217). The page names `backend/tests/link_paths.json` as the cases both test suites read.
* **Update**: [HTTP API](/reference/http-api.md#what-a-move-does-to-the-links) says a folder move carries its images and books and rewrites links to them, and a note's move rewrites links to the books it carries but not to one held back (#218). It says a link inside a fenced block or an inline code span is left as written (#220).
* **Update**: [HTTP API](/reference/http-api.md#what-a-move-does-to-the-links) says a note's move rewrites a markdown link to a book it carries (#221), a fence inside a blockquote or a list item counts as code (#222), and a move writes `#` and `?` as `%23` and `%3F` (#225). The asset, image and page listings and `GET /api/assets/{path}` match a suffix in any case, so `Plan.PDF` is listed and served; a note's `.md` still matches exactly (#226). [Moving notes](/explanation/moving-notes.md) names the six escaped characters.
* **Update**: [HTTP API](/reference/http-api.md#what-a-move-does-to-the-links) says a move also asks rg for the name escaped the way the editor's encodeURI writes it, so a link to `Bücher/x.png` spelled `B%C3%BCcher/x.png`, in either case, follows a folder's move, and one to `Über.md` spelled `%C3%9Cber.md` follows the note's (#230).
* **Update**: [Moving notes](/explanation/moving-notes.md) says an embed, `![](path)`, is read from the vault root the way the editor draws it, so moving the note that holds it leaves it alone and moving the file it shows rewrites it to the new vault path. A plain `[text](path)` is still read from its folder. Before, moving `A/n.md` to `B/n.md` turned its `![](Images/x.png)` into `![](../A/Images/x.png)` (#248).
