# 2026-11-02

* **Fix**: the readers of a todo's parts end them where the writes end them (#1445): at a heading or a list item that is no todo, with fenced lines no todos. The todo pane draws a todo past one at the edge, with no date, priority or client mark from the todo above and nothing added to its `1/2`; the editor's `1/2` counts the same; `<leader>@` reads client work off the same tree and refuses a fenced line with `Nothing moved: that line is code`; and `GET /api/todos` gives a far todo no project from above. To let the pane see them, the route drops fenced lines and, in a note with an indented todo, sends its headings and plain list items with `project: null`. [HTTP API](/reference/http-api/todos.md#fences-and-the-lines-that-end-parts), [Subtasks](/reference/todo-format/state-changes.md#subtasks), [Editor keys](/reference/editor-keys/todos.md).

* **Fix**: a `⛔` on a `🆔` that two todos carry holds only while one of them is open (#544). With both closed the todo pane draws no `⛔` and counts no waiter, and a press that recomputes dependents opens the todo as on any closed blocker. `closedAmong` answers `true` for such an id, so the pane and the writes read one answer. A press in the editor still leaves the dependent where the other twin is in another note, whose state the buffer cannot see. [Todo pane keys](/reference/editor-keys/todo-pane-keys.md) and [presses on a todo row](/reference/save-path-orderings/todo-row-presses.md) say so.

* **Fix**: a frontmatter block closes only on `---` at column 0, with spaces, tabs or a carriage return after it (#654). ` ---`, a space or tab in front, closes nothing, as in Obsidian, so a note whose only closer is indented has no block: its hashes are tags in `GET /api/tags` and in the editor, which draws its first line as a rule. `frontmatter.py`, the client's `note-frontmatter.ts`, the editor's highlighting, the exam reader and the model-use notes read one rule, held to shared cases in `backend/tests/fixtures/frontmatter_closers.json`. The graph reads no `type` from a block that never closes, and the weather card and Format document no longer read a `---` with no closer as a block to the note's end. [Tag format](/reference/tag-format.md).

* **Fix**: a `<!--` opening a list item or a quote hides the tags after it in every reader, as in the editor (#655). `- <!-- x --> #p`, `> <!-- x --> #p` and `1. <!-- x --> #p` carry no tag in `GET /api/tags`, the graph, search, the note header and the deck reader, and a comment indented under a list item hides its tags in the readers of a whole note. `- [ ] <!-- x --> #p` still carries `#p`. The backend finds comment blocks with the markdown-it parser it reads fences with, so a block never closed ends with its item. [Tag format](/reference/tag-format.md).

* **Fix**: an ordered item numbered past 1 under a paragraph keeps the tags after its comment, as in the editor (#1453). In `text`, then `2. <!-- x --> #p`, the line goes on with the paragraph, so `GET /api/tags`, the graph and the note header list `#p` again; `1. a`, then `2. <!-- x --> #p`, still carries no tag. [Tag format](/reference/tag-format.md).
